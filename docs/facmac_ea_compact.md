# 微电网轻量参数方案

配置名称：`facmac_ea_compact`  
日期：2026-10-17

这是新增的轻量候选，原有 `facmac_ea` 和共享默认参数保持不变。
本方案改变了模型容量和每次学习的批量，不再属于与原模型数值等价的执行优化。

## 实际输入和输出

以下尺寸由 `src/direct_main.py` 加载当前 `microgrid` 配置后实测：

| 项目 | 尺寸或含义 |
| --- | --- |
| 智能体数量 | 3 |
| 每个智能体的观测 | 20 维 |
| Actor 的实际输入 | 20 维观测 + 2 维上一动作 + 3 维身份编码 = 25 维 |
| Actor 的输出 | 每个智能体 2 维；3 个智能体共 6 个动作分量 |
| 动作含义 | 发电机出力比例 `[0, 1]`，电池可行充放电比例 `[-1, 1]` |
| 每个智能体的 Critic 输入 | 20 维观测 + 2 维动作 = 22 维 |
| 全局状态 | 3 × 20 = 60 维 |
| 每个回合 | 24 个环境步，回放保存 25 个状态 |

三个智能体共享同一个策略网络。因此 Actor 保持“25 维输入、2 维输出”，
不是改成集中式的“60 维输入、6 维输出”。

## 选定参数

| 参数 | 原配置 | 新配置 | 选择理由 |
| --- | ---: | ---: | --- |
| `rnn_hidden_dim` | 64 | 48 | 给 25 维输入保留时序处理余量，不直接压到 32 |
| `mixing_embed_dim` | 64 | 32 | 3 个智能体的 Q 值融合使用较小嵌入，明显减少超网络生成的矩阵 |
| `hypernet_embed` | 64 | 64 | 不同时压缩 60 维全局状态的非线性映射，降低容量变化风险 |
| `batch_size` | 512 | 128 | 按 CPU 训练需求进一步缩小批量；前一版为 256 |
| `buffer_warmup` | 512 | 512 | 不提前开始训练，避免同时改变预热数据量 |
| `test_interval` | 2000 | 10000 | 减少周期验证开销，但会使最佳检查点选择更稀疏 |
| `fixed_eval_days` | 8 | 8 | 保持验证日覆盖不变 |
| `t_max` | 3000000 | 3000000 | 总环境交互步数不变 |

这里的 48 是容量与速度的工程折中，不是根据输入维度推导出的最优宽度。
输出只有两个动作，并不意味着只需要很小的循环隐状态；电池调度仍涉及
SOC、时间、预测和跨时刻决策。

Actor 和 Critic 共用 `rnn_hidden_dim` 配置，所以它们的隐藏宽度都变为 48。
学习率仍为 Actor `3e-4`、Critic `1e-4`，`gamma=0.99`、
`target_update_tau=0.002` 保持不变。普通更新间隔 2、每次普通更新数 1、
EA 学习更新数 3、每个 EA 周期演化代数 1、种群大小 5 也保持不变。
所有运算仍在 CPU 上使用 float32。
batch 从 256 降到 128 后，每次更新抽取的回合数减半；不增加更新次数，
也不自动修改学习率。总环境步数相同不代表累计参与梯度计算的数据量相同。

算法 YAML 只记录有意改变的项目，其余参数从 `default.yaml` 继承。

## 模型规模

下表只统计在线 Actor、Critic 和 Mixer，不包含目标网络与 EA 种群副本：

| 模块 | 原配置参数量 | 新配置参数量 |
| --- | ---: | ---: |
| Actor | 26,754 | 15,458 |
| Critic | 5,697 | 3,505 |
| Mixer | 174,602 | 62,410 |
| 合计 | 207,053 | 81,373 |

在线参数量减少约 60.7%。生成的主要图权重矩阵每个样本从
`32 × 64 = 2048` 个元素变为 `16 × 32 = 512` 个元素；
再加上 batch 从 512 减到 128，该中间张量的元素数降至原来的十六分之一。
这不是对整个进程峰值内存的测量。

## 检查结果

新增测试通过真实入口加载配置，并验证：

- 原配置和共享训练设置没有被覆盖。
- Actor 输入 25、隐藏宽度 48、输出 2，Critic 输入 22。
- Mixer 宽度 32，超网络隐藏宽度 64。
- 实际训练跨过原来的 512 回合预热，使用 128 回合的学习批量。
- 完成 8 次学习器更新和 11 次 EA 演化。
- Actor 参数确实更新；网络参数和梯度保持有限值且在 CPU 上。

batch=128 的测试记录：`results/facmac_compact_batch128_tests_20261017_a.log`。
前一版 batch=256 的测试记录为 `results/facmac_compact_tests_20261017_a.log`。
此前 batch=256 的完整测试套件共 66 项通过，记录在
`results/facmac_compact_suite_20261017_a.log`。

此前 batch=256 的真实训练计时运行了 14,400 个环境步、45 次学习器更新和 18 次演化，
总计约 20.65 秒，学习器单次更新平均约 0.077 秒。
这只是短跑的运行检查，并未进行训练结束后的效果对比。

## 速度与效果的边界

以下为此前 batch=256 版本的历史数据，不是当前 batch=128 的测速。
六线程、相同序列长度、交替执行的小基准中，预热两次后计时八次：

| 项目 | 原配置 | 前一版轻量配置（batch=256） |
| --- | ---: | ---: |
| 单次更新平均耗时 | 0.290 秒 | 0.082 秒 |
| 每次学习的回合数 | 512 | 256 |
| 更新次数吞吐比 | 1.00 | 3.55 |

这包含了减小 batch 的贡献，不是相同学习工作量下的纯执行提速。
不能据此声称达到相同收益会快 3.55 倍，也不能据此认定效果不下降。
后台负载和短样本计时还会影响具体数值。

计时记录：

- `results/facmac_compact_paired_20261017_a.json`
- `results/facmac_compact_training_20261017_a.csv`

下一步应使用相同固定验证日和多个种子，比较完整经济成本、成本节省额、
约束违例以及达到目标收益所需的实际时间，再决定是否替代原配置。

## 使用

```powershell
uv run python src/direct_main.py --config facmac_ea_compact --env-config microgrid
```

本地短跑、不上传 W&B、不保存模型：

```powershell
uv run python src/direct_main.py --config facmac_ea_compact --env-config microgrid --override wandb_mode=disabled --override save_model=False --override t_max=12500
```

由于网络宽度改变，新配置需要重新训练，不能直接续训旧的 64 维模型权重。
评估旧检查点时应使用其保存的原始配置和源码快照。
