# 实验评估与溯源

运行配置和命令见[项目 README](../README.md)。
本文记录跨实验适用的评估要求，不保存临时 PID、队列或预计完成时间，
也不授权启动、重启或扩展训练。
原含交叉 v03 的执行协议保留在[历史记录](archive/paper_execution_v03.md)。

## 数据与模型选择

- 源 CSV、训练/验证/保留时段和预测信息范围必须明确并冻结。
- 只用固定验证集选择检查点，不用测试成本挑种子、参数或 Actor。
- 主要结果使用预先指定的 RL Actor；EA Actor 单列，不能每天挑更好的一个。
- 当前保留测试时段曾用于环境和物理诊断，只能称为回顾性保留评估。
  真正独立的外部验证需要未使用过的数据，不能把现有验证日重新贴标签。
- 普通入口未完整固定 Python、fastrand 和 Gym 随机源，不宣称严格配对复现。

## 成本与库存

报告整个固定评价时段及每个种子的原始成本、分项成本、最差日和波动，
不只报告选出的优秀日。区分货币 `economic_cost` 与包含其他项的 `full_cost`。

连续 SOC 评价与每日独立重置的展示是不同任务。所有对照需说明期初、期末库存，
并报告购电、发电、充放电、互济和弃光。日末 SOC 不闭合不是持续库存任务的物理违规。

展示中的绝对 SOC 偏差修正同时惩罚库存增加和减少，只是诊断，
不是准确的终端库存价值，也不是环境奖励。
MILP 必须披露完美预测信息、库存边界、求解状态、时间和 gap；
日循环 MILP 不自动构成非循环 RL 的严格成本下界。

## 预算与检查点

总训练交互包含 EA 种群 rollout，同时报告学习更新次数、采样协议和墙钟时间。
同环境步不意味着同外生日覆盖或同计算量。

检查点的 Actor、源码快照、配置和数据哈希必须可追溯。
源码改名或其他变更后，使用经过核验的保存源码加相同数据评估；
不改原 metadata，不取消校验，不把只含 Actor 的保存点称为完整续训状态。
保留失败和中止证据，不将其计为正常完成或覆盖后伪装成一次成功运行。
