# PPO 库存奖励迭代

## 目标与不变项

延续当前三智能体微电网的独立代表日 PPO 诊断。
只调整 `tools/sb3_dispatch_reward_env.py` 的实验奖励，
不改设备参数、原 CSV、动作映射、观测维数或 FACMAC 默认奖励。
每天从 SOC 0.35 开始，24 步真正终止，不接入次日价值。
这不是持续跨日 FACMAC 任务的自动替换方案。

## 奖励公式

旧期末库存偏差费用为：

```text
k_i = 1.25 * (train_max_tariff + cycle_cost_i) / eta_charge_i
e_i = capacity_i * (SOC_i - 0.35)
U_i = capacity_i * (soc_max - soc_min)
P_L1 = sum_i k_i * abs(e_i)
```

本轮测试的期末目标：

```text
P = inventory_weight * P_L1
    + inventory_quadratic * sum_i k_i * e_i^2 / U_i
```

其单位仍为场景 CU。二次项加重较大库存偏差，
不是电池实际退化费，也不应与运行电费混为一谈。
正负偏差对称、各电池单独计算，不允许容量间抵消。

截止时间势函数：

```text
Phi(h, SOC) = -(h / 24)^deadline_power * P(SOC), h < 24
Phi(terminal) = 0
r = r_original + reward_scale/N * (gamma * Phi_next - Phi_now)
r_last -= reward_scale/N * P(SOC_end)
```

PPO 与势函数使用同一 gamma 0.99。
初始库存偏差为零，终点势函数显式归零，
所以原始折扣回报的塑形增量累计为零；
新增的真实任务目标只有期末库存费用。
没有奖励正负动作切换、吞吐量或设备运行时数。
动作完全由 PPO 给出，没有参考动作、MILP 示范或库存强制回填。

## 预先固定的验收标准

每个种子单独在固定六个验证日检查，不能只看团队或日期平均：

- 所有电池、所有日末 SOC 绝对误差不超过 0.03。
- 所有电池、所有日子的 SOC 跨度至少 0.48。
- 每块电池每天至少各有两小时有效充电和放电，
  功率阈值为对应额定功率的 1%。
- 平均实际运行成本不超过同输入、初始/日末 SOC 0.35 的
  完美预测 MILP 日循环参考成本的 1.05 倍。

MILP 有完美预测和严格日末等式，PPO 为因果观测和软惩罚，
所以该成本比较是工程验收参考，不能称为同一可行域下的严格最优差距。
验证参考约 1832.77 CU/天，来源为
`results/oracle_milp/battery_activity_diagnosis_20261017_a/`。
启动前核对其物理环境和输入数据哈希。

此外检查逐小时曲线、发电/购电/交换和第二块电池午间回充，
不以增加动作次数或通过指标阈值代替对调度含义的判断。

## 第一轮

三个方案均用 seed 0、240,000 环境步：

- `terminal_ref`：原单独期末 L1 惩罚，同预算对照。
- `deadline_q16`：截止时间势函数，二次项系数 16。
- `deadline_q64`：截止时间势函数，二次项系数 64。

前置 `preflight_20261017_a` 每组仅 2400 步，
只验证训练、保存重载和汇总链路，不计入策略效果。
正式目录：`results/sb3_reward_tuning/pilot_20261017_a/`。

```powershell
uv run python tools/run_sb3_reward_tuning.py --output results/sb3_reward_tuning/<new-name> --recipes terminal_ref deadline_q16 deadline_q64 --timesteps 240000 --seeds 0 --workers 2
```

若全部失败，根据失败类型调整奖励，而不是降低既定验收阈值。
选定方案后，用多个种子复核最终策略，不挑最好训练时刻。
物理配置经 `src/direct_main.py` 的加载/合并函数读取，
每一轮均保存环境、配置、实验代码、依赖清单与锁文件快照。

## 第一轮结果与第二轮设计

第一轮三个方案均未通过日末库存标准，未读取测试集：

| 方案 | 平均运行成本 CU/天 | 平均库存误差 kWh | 最差日末 SOC 误差 |
| --- | ---: | ---: | ---: |
| terminal_ref | 1883.85 | 69.59 | 0.1500 |
| deadline_q16 | 1892.14 | 36.80 | 0.0797 |
| deadline_q64 | 1922.99 | 37.33 | 0.0825 |

三组均满足有效充放电和 SOC 跨度标准。
误差诊断发现，末步动作经常饱和为满额定充电，
第三块电池从 0.2 直接充到 0.386，第二块可充到 0.4325。
保存策略中的电池动作探索标准差仍约 0.4..0.7。
这不是“没有执行充电”，而是末步恢复不够精确。

第二轮统一把初始 log_std 从 0 降为 -1（标准差约 0.368），
同时重跑原奖励对照，不能将两轮的变化全部归因于奖励。
仍用 seed 0、每组 240,000 步，对比
terminal_ref、deadline_q16、market_q16。
目录为 `results/sb3_reward_tuning/pilot_20261017_b/`。

market_q16 保持同样的期末费用，但更换非终止状态势函数：

```text
Phi(h, SOC) =
    sum_i eta_discharge_i * max(published_tariff[h:24]) * e_i
    - clip((h - 20) / 4, 0, 1)^2 * P(min(SOC, initial_SOC))
Phi(terminal) = 0
```

公开周期电价来自训练日 0；核心环境已校验所有日期使用同一电价。
不读取未来实际 PV、负荷或验证/测试最优动作。
库存压力只对临近截止时间的缺口提供信号，避免中途高 SOC 被塑形强烈排斥。
期末费用仍对正负偏差对称计费；势函数仍在完整折扣回报中抵消。

```powershell
uv run python tools/run_sb3_reward_tuning.py --output results/sb3_reward_tuning/<new-name> --recipes terminal_ref deadline_q16 market_q16 --timesteps 240000 --seeds 0 --workers 2 --log-std-init -1
```

多种子复核阶段先不启用测试集。
只有选定奖励至少三个种子均通过验证标准后，
`--evaluate-holdout --selected <recipe>` 才允许恢复已经冻结的最终模型，
在预留的新测试日期评估一次，且不重新训练或替换最佳检查点。

## 第二轮结果与第三轮设计

第二轮库存误差变小，但形成了少用电池的局部解，全部未通过标准：

| 方案 | 平均运行成本 CU/天 | 平均库存误差 kWh | 最差日末 SOC 误差 | 最小日内 SOC 跨度 |
| --- | ---: | ---: | ---: | ---: |
| terminal_ref | 1913.52 | 49.18 | 0.1177 | 0.1500 |
| deadline_q16 | 1962.13 | 11.78 | 0.0393 | 0.1100 |
| market_q16 | 1957.65 | 11.95 | 0.0458 | 0.1460 |

第二轮不支持“只需减小探索就能变好”。
第三轮固定终点预算 600,000 步，terminal_ref 与 market_q16 同步：

1. 0..120,000 步：库存奖励强度为零，先学经济调度。
2. 120,000..240,000 步：库存奖励强度线性升至 1。
3. 之后保持最终奖励，直至完整训练结束。

从 120,000 步开始，在收集每个新 rollout 之前，
将策略的 log_std 上限从初始 0 平滑降到 log(0.08)，
240,000 步内完成该下降，之后保持上限。
这个日程对所有候选和对照完全相同；
不在 rollout 收集和对应 PPO 更新之间修改分布。
这是探索日程调整，不是纯奖励消融，须与前两轮分开解释。
强度变化阶段为非平稳训练目标，势函数累计恒等式只对固定强度阶段成立。

`curriculum_preflight_20261017_a` 以缩短的阶段检查完成 PPO 更新、
模型保存重载与共同预热权重哈希相同。
正式目录为 `results/sb3_reward_tuning/pilot_20261017_c/`。

```powershell
uv run python tools/run_sb3_reward_tuning.py --output results/sb3_reward_tuning/<new-name> --recipes terminal_ref market_q16 --timesteps 600000 --seeds 0 --workers 2 --curriculum
```

后续若扩展种子数，只能在环境、奖励、训练日程、代码哈希、
步数和日期协议完全相同的情况下复制已完成的重叠种子。
原结果不修改，新目录记录来源路径和策略哈希。

## 第三轮单种子结果

| 方案 | 平均运行成本 CU/天 | 平均库存误差 kWh | 最差日末 SOC 误差 | 最小日内 SOC 跨度 | 验收 |
| --- | ---: | ---: | ---: | ---: | --- |
| terminal_ref | 1876.71 | 33.78 | 0.1500 | 0.5684 | 失败 |
| market_q16 | 1879.39 | 4.21 | 0.0226 | 0.5721 | 通过 |

market_q16 所有验证日均双向使用电池，实际成本比日循环 MILP 参考高约 2.54%。
它没有降低不闭合库存对照的实际成本，而是以约 2.69 CU/天的增加，
显著缩小期末库存缺口。不能把这一结果称为电费下降。
三个电池平均日末 SOC 误差约 0.00675，最差 0.02259；
这是达到指定工程容差，不是数学上严格日循环。

逐小时图显示，电池仍然有较长的待机时段，第二块电池未完全学到
完美预测 MILP 中部分日期的午间回充。这是尚存的调度质量差距，
不应仅因验收通过就抹去。当前目标是经济合理、无明显库存透支的调度，
不是复制最优动作或证明收敛。

多种子验证目录：
`results/sb3_reward_tuning/confirmation_20261017_a/`。
使用 seed 0、1、2，六个运行均为 600,000 步，
其中两项 seed 0 在源哈希和完整协议相同检查后从第三轮复制。
多种子训练和验证完成前没有读取测试集。

## 最终确认结果

第三轮冻结的 `market_q16` 在三个种子均通过验证标准后，
只对保存的最终模型执行一次预留测试日评估。
没有利用测试结果继续调奖励或选择模型。

### 同预算多种子验证

| 奖励 | 通过种子 | 成本 CU/天 | 库存绝对误差 kWh | 全部电池/日期最差 SOC 误差 |
| --- | ---: | ---: | ---: | ---: |
| terminal_ref | 1/3 | 1881.94 | 28.74 | 0.1500 |
| market_q16 | 3/3 | 1879.91 | 3.57 | 0.0226 |

market_q16 每个种子的最终结果：

| seed | 成本 CU/天 | 库存误差 kWh | 最差日末 SOC 误差 | 最小 SOC 跨度 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 1879.39 | 4.21 | 0.02259 | 0.57215 |
| 1 | 1882.01 | 4.01 | 0.01637 | 0.59998 |
| 2 | 1878.32 | 2.48 | 0.00927 | 0.60000 |

验证集平均 SOC 跨度为 0.5970，占 0.6 可用区间约 99.5%。
所有种子、日期、电池都满足有效双向使用。
团队平均充电 641.70 kWh/天、放电 556.59 kWh/天；
二者不同主要来自 0.93 * 0.93 的往返效率，
不能仅以充放电 kWh 不等断言库存不守恒。
最差库存残差在预定容差内，但并非严格归零。

原期末惩罚在 seed 1 也通过了，说明足够训练和探索日程同样重要。
新奖励的优势主要是三个种子都恢复了库存，
不是显著降低运行成本；其成本相对对照仅小幅下降，
不足以宣称经济性能有统计显著提升。

各模型已在测试前固定，不再重新训练：

| 奖励 | 通过种子 | 成本 CU/天 | 库存绝对误差 kWh | 最差日末 SOC 误差 |

三个 market_q16 的最差日末 SOC 误差分别为
0.02092、0.01583、0.00689，未出现此前前两块电池持续日末耗空的问题。

测试后仅为解释结果计算了同日期完美预测 MILP，
不再触发任何模型或奖励选择。20 个 MILP（电池开/关各 10 日）
均达到最优状态，并通过物理环境重放检查。

- 严格日循环 MILP：1898.71 CU/天。
- 无电池重新优化：2010.82 CU/天。
- market_q16 PPO：1943.23 CU/天，比前者高约 2.34%，比后者低约 3.36%。

成本差仍是参考对比：PPO 有因果观测和软库存容差，
MILP 有完美预测和严格库存等式，不能把 2.34% 称为严格最优性 gap。
验证和测试合计仅 16 个日期、3 个训练种子，
不是所有季节/极端天气的保证，也未证明长期收敛。

### 其他设备与剩余差距

market_q16 验证集平均每台发电机有效工作约 16.96 小时/天，
团队发电约 5050 kWh/天、购电约 7137 kWh/天、
社区送出约 1928 kWh/天。
测试集对应约 17.47 小时、5512、7099、1992 kWh/天。
没有通过关掉发电/交换设备来换取库存指标。

保留的不足：部分电池放电仍偏早、午间回充机会仍有遗漏。
当前已达到“经济上能解释、明显利用电池、不过度透支起始电量”的基线，
不是最优调度，也不要求电池全天动作。
