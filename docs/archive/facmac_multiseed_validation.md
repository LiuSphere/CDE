# FACMAC 环境多种子对照

## 结论

正式矩阵的 20 次训练均已完成，共 400,800 个实际训练环境步。
本轮只测试已有 v2/v3，没有实施后来提出的邻居信息或时间边界新方案。
纯 FACMAC 的新环境平均成本略低，但 5 个种子中只有 3 个改善，
而且电池策略没有学会日内充放电循环。**尚不能认定 v3 稳定地更适合 FACMAC。**

## 完整结果

以下均使用训练结束时的策略，正改善率表示 v3 成本较低。
EA 组实际为 20,064 步，无 EA 组为 20,016 步；每个算法内 v2/v3 步数完全一致。

| 策略 | v2 平均成本 CU/天 | v3 平均成本 CU/天 | 配对改善率均值 ± 种子间标准差 | 改善种子 |
| --- | ---: | ---: | ---: | ---: |
| 纯 FACMAC，无 EA | 2431.62 | 2393.52 | 1.47% ± 5.26 个百分点 | 3/5 |
| FACMAC + EA 的主策略 | 2454.48 | 2359.25 | 3.85% ± 3.87 个百分点 | 4/5 |
| FACMAC + EA 的 EA 精英 | 2420.00 | 2328.64 | 3.73% ± 4.12 个百分点 | 3/5 |
| 补充：RL/EA 较优候选 | 2419.04 | 2319.81 | 4.06% ± 3.66 个百分点 | 4/5 |

改善率是五个逐种子比值的均值，不是两列总平均成本的比值。
标准差不是置信区间，本文不作显著性或长期收敛结论。

| 种子 | 纯 FACMAC 改善 | 带 EA 的主策略改善 | EA 精英改善 |
| --- | ---: | ---: | ---: |
| 0 | 6.11% | 1.48% | 5.64% |
| 1 | 7.19% | 9.95% | 7.24% |
| 2 | -2.39% | -0.03% | -0.38% |
| 3 | 1.41% | 2.89% | -1.05% |
| 4 | -4.97% | 4.96% | 7.20% |

纯 FACMAC 最差种子退化 4.97%，不能把平均值当作稳定改善。
无 EA 对照更直接反映环境学习接口；带 EA 的对照还包含公共场景适应度协议的影响。
本表也不是在证明 EA 优于无 EA：两组的默认更新日程和采样构成不同。

### 储能诊断

v3 纯 FACMAC 的种子 0、1、2 在六个验证日均没有充电，
每日总放电约 139.5 kWh，末尾 SOC 均为 0.2：
恰好是把初始 SOC 0.35 到下限 0.2 的可用电量耗尽。
种子 3、4 每日总充电约 483.87 kWh、放电为零，末尾 SOC 均为 0.8。
因此这五个策略均未学到有意义的日内双向循环。

| 策略 | v2 平均末尾 SOC | v3 平均末尾 SOC |
| --- | ---: | ---: |
| 纯 FACMAC | 0.591 | 0.440 |
| 带 EA 的主策略 | 0.586 | 0.273 |
| EA 精英 | 0.489 | 0.324 |
| 较优候选 | 0.452 | 0.200 |

末尾库存不同，会影响单日运行成本解释，尤其不能把较低库存全部当成可持续节费。
下一步更有价值的是统一库存/时间边界评价并增加训练预算，再判断接口改善；
本轮没有为得到更好数字而追加改参或筛选种子。

## 固定实验协议

实验目录：`results/facmac_environment/multiseed_20261017_b/`。
五个种子为 0、1、2、3、4。
每个种子运行 v2/v3 两个环境版本，分别使用 `facmac_no_ea` 和 `facmac_ea`，
共 20 次独立训练，每次请求 20,000 个训练环境步。
没有重新调整环境或学习率，也不根据中途成绩删选种子。

所有训练由 `src/direct_main.py` 加载默认、环境、算法 YAML 和显式 overrides。
批量 512、warmup 512、buffer 100000、更新频率、EA 世代数等不变。
验证使用相同六个日期行 740、766、808、862、880、904，
每天初始 SOC 均为 0.35。没有使用测试集选择环境或策略参数。

## 随机源与源码隔离

旧两种子短检只由入口固定 NumPy/Torch，EA 使用的 Python random/fastrand、
动作空间自身随机源没有完整固定，因此本轮全部重跑，不直接混用旧结果。

日志系统初始化之后、模型构造之前重新固定：

- Python random、fastrand、NumPy、Torch。
- 各智能体 Gymnasium 动作空间，种子为实验 seed 加智能体索引。
- 单进程 Torch CPU 线程数为 1，开启确定性算子检查。
- 批量启动子进程的 `PYTHONHASHSEED` 也固定。

最多同时运行两个 CPU 任务，避免过多 replay 内存占用。
墙钟时间不是本次算法效果指标，两个并行任务的耗时不用于吞吐优劣结论。

工作区另有性能优化改动，因此没有直接读取持续变化的生产源码训练。
v2 来自 tag `microgrid-heterogeneous-exchange-v2` 的源码快照；
v3 在此基础上覆盖此前已验证的环境、环境 YAML、runner 和场景比较协议。
两个快照共同采用相同的策略推理/回放采样优化，避免把性能版本差异混作环境收益。
这些优化通过动作/隐状态相等、采样独立性等回归检查。

源码逐文件核对后，v2/v3 仅以下四个文件不同：

```text
src/config/envs/microgrid.yaml
src/envs/maenv.py
src/run.py
src/runners/episode_runner.py
```

全部快照源码和数据哈希见 `experiment.json`；
每次运行保存实际合并配置、随机协议、训练结束时的步数和最终验证。
训练末尾验证使用当前 RL 网络与最后一代 EA 精英，不使用过时的中途精英。
所有验证轨迹均不计入训练 `t_env`。

## 统计口径

主指标是六个固定验证日的平均运行成本：

```text
operating_cost = full_cost + battery_punishment_reward
```

旧版 punishment_reward 为负，因此上述定义排除不可行请求罚款。
购电、发电、排放代理、储能吞吐退化和输送费用仍全部计算。
新旧版本回报的绝对数值不直接比较。

分别报告：

1. 纯 FACMAC（无 EA）的最终主策略。
2. FACMAC + EA 的最终 FACMAC 主策略。
3. FACMAC + EA 的最终 EA 精英。
4. 补充项：在相同六个验证日上，从主策略/EA 精英中选择平均成本较低者。
   这不是按每天择优拼接一个不存在的策略。

对每个相同 seed、相同算法的 v2/v3 计算：

```text
improvement_pct = 100 * (1 - v3_cost / v2_cost)
```

正数表示 v3 成本较低，负数表示更差。
改善/变差计数采用 `1e-6` 个百分点的数值容差，避免浮点噪声被算作改善。
均值、样本标准差、改善种子数均以五个种子为统计单位；
六个验证日不被当成六个独立训练重复。
不挑最好训练时刻，不用历史回报峰值替代最终策略评估。
配对两侧还必须具有相同的实际训练步数、验证日期和随机控制协议。

同时保存充放电量和末尾 SOC。
验证日没有强制日末 SOC 等于初始值，因此成本是非循环策略成本，
不能直接作为与日循环 MILP 的最优差距。

## 结果与边界

最终统计保存在实验目录的 `analysis/summary.json`，
每个 seed 的原始配置和最终验证保存在 `runs/`。
点图将纯 FACMAC、带 EA 的主策略、EA 精英分开；
每个编号点对应一个种子，黑色菱形与竖线表示均值和标准差。
绿色点为新环境成本较低，红色点为较高；零线上方表示改善。
标准差不是置信区间或显著性证明。

本次只扩展种子数，单次仍为 20,000 步：
512 个 24 小时 episode 的 replay warmup 占约 12,288 步。
因此仍然是较早期的学习检查，不足以证明长期收敛、最终最优性或 EA 优越性。
观察维数不同也会改变同一 seed 下的网络初始化，
本轮属于 v2/v3 整包对照，不是四项环境改动的逐项消融。

## 失败与复现

Windows uv 间歇性启动权限错误发生在 Python 开始前。
启动日志逐次保留；只有确定尚未创建训练目录的此类错误才允许重试。
真实训练异常会报错，未完成或缺失的种子不进入统计。
恢复运行只能复用通过源哈希、随机协议、完整最终评估验证的结果；
实验协议和源码不可在恢复时改变。
第一次批量运行完成了 18 次训练，另两项在 Python 开始前因 uv 权限错误中止；
恢复阶段只训练缺失两项，其他 18 项完整复用并重新核验。
`completed.json` 中的 `seconds` 记录恢复阶段耗时，不是整个矩阵的总墙钟时间。

预检目录 `multiseed_20261017_a/` 用于验证最终策略捕获流程，
不与正式五种子矩阵合并。

```powershell
uv run python tools/run_microgrid_multiseed.py --experiment results/facmac_environment/multiseed_20261017_b --seeds 0 1 2 3 4 --timesteps 20000 --workers 2
# 仅在未完成的同一矩阵上恢复，不覆盖已完成结果：
uv run python tools/run_microgrid_multiseed.py --experiment results/facmac_environment/multiseed_20261017_b --seeds 0 1 2 3 4 --timesteps 20000 --workers 2 --resume
uv run python tools/analyze_microgrid_multiseed.py --experiment results/facmac_environment/multiseed_20261017_b
```

原有实验、源码快照和训练日志未删除；没有自动提交或推送。
