# H03: Two Critic Updates Per Actor Update

Registered2026-10-22 before algorithm edits. Status: preregistered,
not implemented or economically assessed.

## Conjecture And Evidence

The current single-critic learner updates its Actor after every Critic step,
including each of the three replay updates following an EA cycle
(`src/learners/gavdac_learner.py:train`, `src/run.py`). Holding the Actor fixed
for one intervening Critic update may give the value estimator more adaptation
before the policy exploits it. This may improve retained economic dispatch.
No diagnostic currently establishes excessive policy-update frequency as the
cause of this project's performance gap. H02's result is not such evidence.

Primary motivation checked2026-10-22:
Fujimoto, van Hoof and Meger, ICML2018, PMLR80:1587-1596,
https://proceedings.mlr.press/v80/fujimoto18a.html
and the authors' implementation
https://github.com/sfujim/TD3/blob/master/TD3.py .
The paper motivates delayed policy updates; the implementation uses
policy_freq=2 and delays target updates as well. H03 deliberately isolates
Actor optimizer cadence: target updates retain the baseline frequency.
It is neither full TD3 nor an exact reproduction of its delayed schedule.
Those references do not establish a benefit for this microgrid.

## Sole Intervention

Opt-in `actor_update_interval: 2` in `gavdac_c2_h03`, inherited from main.
Count successfully completed Critic optimizer steps globally across all
learner calls, including EA-triggered calls. On steps1,3,5,... skip the
Actor loss/backward/clip/optimizer entirely; on steps2,4,6,... execute the
unchanged Actor phase after the Critic step using that call's batch/history.
Never reuse a skipped call's Actor graph on a later batch.

All target networks continue updating after EVERY Critic step with the
original mode/tau, including skipped Actor steps. Keep Critic update cadence,
replay sampling, losses, optimizers, learning rates, gradient clipping,
Actor live mixer-context gradient and regularizer unchanged. No twin critic,
target smoothing, policy noise, delayed targets or EA changes.

Missing interval or explicit1 must preserve the baseline complete update.
Reject bool, non-integer or values below1. Parameter counts are unchanged;
Actor optimizer steps are halved (floor(Critic steps/2)), so this is not
matched optimizer compute. Physical interaction budget remains6M including EA.
An external EA/RL Actor transfer does not reset this global Critic counter.
