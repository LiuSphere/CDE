# 当前微电网的 PPO 奖励实验

## 目的与范围

检查当前 `facmac_dispatch_v3` 中，改进奖励能否同时改善经济调度、
电池双向使用和期末库存。只新增诊断工具，没有修改主训练环境、
设备参数、源 CSV 或 FACMAC 的默认奖励。

工具为中心化 SB3 PPO：一个策略读取三个智能体的 60 维联合观察，
输出 6 维联合连续动作。这不是 IPPO，也不能证明分散 FACMAC 会获得同样效果。
旧 `tools/train_sb3_microgrid_ppo.py` 仍仅对应 sep 原版快照。

## 三种奖励

以团队合计量记号，`s` 为原环境 reward_scale，`N=3`：

```text
current:   r = s/N * (baseline_cost - full_cost)
terminal:  r = current - s/N * P_end       # 仅最后一步扣除
potential: r = terminal + s/N * (gamma * Phi_next - Phi_now)

P_end = sum_i k_i * capacity_i * abs(SOC_end_i - 0.35)
k_i = 1.25 * (max_train_tariff + cycle_cost_i) / eta_charge_i

Phi = sum_i capacity_i * (SOC_i - 0.35) * eta_discharge_i * mean_train_tariff
Phi_terminal = 0
```

惩罚单位为场景 CU，电量偏差以储存侧 kWh 计。
惩罚系数来自训练侧最高补电电价和吞吐成本，乘 1.25 余量，
而非根据验证或测试表现搜索。对每个电池分别取偏差绝对值，
不能用一块电池充满去抵消另一块电池耗空。
它是软惩罚，**不是强制日末 SOC 等于起点**。

势函数只使用公开周期电价的训练侧均值和当前 SOC。
它不读取未来实际负荷、PV 或最优调度动作。
充放电、发电和交换都没有额外的设备活跃奖励。
`Phi_initial=Phi_terminal=0`，因此原始奖励的折扣累计塑形增量为零；
势函数改变学习信号分配，不额外补贴吞吐。
PPO 与塑形使用相同的 `gamma=0.99`。

参考实现与接口说明：

- SB3 官方 VecEnv 文档：`https://stable-baselines3.readthedocs.io/en/master/guide/vec_envs.html`
- imitation 官方势函数奖励实现：`https://imitation.readthedocs.io/en/stable/_modules/imitation/rewards/reward_nets.html`

## 公平对照

三个奖励版本均为独立的 24 小时有限时域任务：
每次 reset 从训练集 0..730 随机选日，所有电池从 SOC 0.35 开始；
第 24 步返回 `terminated=True, truncated=False`，不对次日价值自举。
这一边界协议与 FACMAC 主训练中跨日保持库存的协议不同，
但三组 PPO 内完全相同。不能把本次 current 组直接当成先前 FACMAC 的重复。
本方案如迁回 FACMAC，必须同时明确时间边界，而不能仅复制奖励公式。

种子 0、1、2；三组各请求 120,000 联合环境步，共 9 次训练。
所有结果均来自训练结束时的策略，不挑最好种子或最好检查点。
每个 seed 的三种奖励必须通过初始策略权重哈希相同检查。

- 验证日：740、766、808、862、880、904。
- 预先固定的测试日：913、940、980、1020、1060、1090。
- 测试集仅在每次训练结束后评估一次，不用于选参。
- CPU，每进程一个 Torch 线程，最多两个训练进程并行。
- `n_steps=2400`，`batch_size=240`，`n_epochs=10`。
- 学习率 0.0003，gamma 0.99，GAE 0.95，clip 0.2。
- 策略和价值网络均为两层 64 单元，ent_coef 0。
- 不归一化观察；训练侧归一化奖励，不裁剪归一化后的奖励。
- 完整记录 Python、NumPy、Torch、Gymnasium、SB3 版本与随机协议。

## 指标解释

分别报告实际运行成本和统一的期末偏差调整分数：

```text
operating_cost = sum(full_cost)
inventory_adjusted_score = operating_cost + P_end
```

第二项不是实际电费，也不是日循环 MILP 的最优性差距。
它用于给三组使用同一口径评价初始电量消耗与日末积压。
报告的日成本不折扣，PPO 训练目标按 gamma 折扣，两者不完全相同。
VecNormalize 是训练侧自适应缩放；势函数的累计恒等式指缩放前的原始奖励。

同时保存每块电池的充放电量、末尾 SOC、SOC 跨度和有效充放电小时数。
“双向使用”要求每块电池每天至少各有两小时的实际充电和放电，
功率均超过相应额定上限的 1%。该指标不等于有效套利或完整循环，
必须与成本、SOC 跨度及期末误差合看。
SOC 总览是容量加权平均，不能替代逐电池记录。

uv run python -m unittest discover -s tests -p test_sb3_dispatch_rewards.py -v

分析时检查所有运行完成、配对步数、初始策略哈希、固定日期、

## 实验结果

正式 9 次训练均完成，每次实际 120,000 步，合计 1,080,000 步。
所有冻结源码、配对初始权重和最终策略重载检查通过。
以下为三个种子均值，每个种子先对相同六个日期求均值。
详细结果以正式目录中的 `analysis/summary.json` 为准。

### 验证集

| 奖励 | 运行成本 CU/天 | 加期末惩罚分数 CU/天 | 期末电量绝对偏差 kWh | 充电 kWh/天 | 放电 kWh/天 |
| --- | ---: | ---: | ---: | ---: | ---: |
| current | 1894.13 | 1956.18 | 149.54 | 486.83 | 560.13 |
| terminal | 1898.79 | 1937.56 | 93.43 | 550.25 | 562.80 |
| potential | 1896.99 | 1934.86 | 91.26 | 564.37 | 573.00 |

相对 current，terminal 的配对调整分数改善为
`0.95% +/- 0.18` 个百分点；potential 为 `1.09% +/- 0.27` 个百分点。
这里的 `+/-` 为种子间样本标准差，不是置信区间。
两种修改均为 3/3 种子改善这一分数。
势函数组的期末电量绝对偏差均值减少 38.97%，但远未清零。
实际运行成本没有改善：potential 均值比 current 高约 2.86 CU/天，
不能把约 1.09% 的调整分数改善称为电费下降。

| seed | current 分数 | terminal 分数 | potential 分数 |
| --- | ---: | ---: | ---: |
| 0 | 1954.64 | 1937.94 | 1939.27 |
| 1 | 1958.70 | 1942.11 | 1935.76 |
| 2 | 1955.20 | 1932.62 | 1929.54 |

terminal 和 potential 在同一库存目标下更可比。
势函数相对单独期末惩罚的验证分数优势只有约 2.70 CU/天，
种子 0 还略差，不能认定有稳定、显著的额外收益。

### 独立测试日

| 奖励 | 运行成本 CU/天 | 加期末惩罚分数 CU/天 | 期末电量绝对偏差 kWh |
| --- | ---: | ---: | ---: |
| current | 2043.57 | 2105.81 | 150.00 |
| terminal | 2049.19 | 2087.70 | 92.82 |
| potential | 2049.45 | 2087.07 | 90.68 |

测试集配对调整分数改善分别约 0.86% 和 0.89%，各为 3/3 种子改善。
势函数相对单独期末惩罚只有约 0.63 CU/天优势，
而实际运行成本反而略高。测试日没有触发任何追加选参或训练。

### 电池与其他设备

三种奖励、三个种子、全部六个验证日及六个测试日的每块电池，
都满足至少各两小时实际充放电的双向使用标准。
current 的平均 SOC 跨度已达 0.588，占 0.6 可用区间的约 98%。
因此本轮**不支持“必须改奖励才能让 PPO 使用电池”**。

但双向使用并不代表期末库存合理：

| 奖励 | agent1 平均末尾 SOC | agent2 平均末尾 SOC | agent3 平均末尾 SOC |
| --- | ---: | ---: | ---: |
| current | 0.2000 | 0.2000 | 0.2008 |
| terminal | 0.2000 | 0.2051 | 0.2928 |
| potential | 0.2001 | 0.2048 | 0.2964 |

修改奖励主要让容量 600 kWh 的 agent3 在日末补回部分电量；
容量 220/180 kWh 的前两个电池仍接近下限。
容量加权 SOC 曲线会掩盖这种差别，须同时查看逐电池图和原始轨迹。
所有组仍不满足严格的每日库存闭合。

验证集上，三组平均每台发电机每日有效运行约 17.3..17.5 小时；
发电约 5091..5127 kWh/天，外网购电约 7005..7038 kWh/天，
社区交换送出约 1873..1875 kWh/天。其他设备没有因库存奖励而停止参与。

### 判断与后续

本轮奖励尝试部分有效：减少期末耗空，但没有实现库存闭合，
也没有降低实际运行成本。势函数的额外收益小，不建议仅凭这次结果
将它作为 FACMAC 默认奖励。

PPO 在原奖励下也学到了较充分的电池使用，说明当前物理环境具备这种能力。
这不证明 PPO 算法优于 FACMAC：中心化信息、训练预算、算法与日期重置协议
同时不同，不能用它归因先前 FACMAC 20,000 步实验的失败。

下一步若继续，应先明确研究的是跨日持续运行还是每日库存闭合。
前者需要连续多日库存评价；后者需要对齐 FACMAC 的终止/重置协议，
并专门解决较小电池的期末补电信用分配。本轮没有自动改动主环境。
