# FACMAC + EA 微电网论文实验计划

日期：2026-10-18（北京时间）

状态：计划草案，仅编写文档；不代表已实现 MAPPO 或已启动本计划的批量实验。

## 1. 目标与范围

面向能源应用类论文，以可控的实验规模回答三个问题：

1. FACMAC + EA 能否降低微电网运行成本，并满足设备物理约束？
2. 相比纯 FACMAC 和独立多智能体基线，是否具有经济性、样本效率或稳定性优势？
3. EA、变异、交叉分别贡献了什么？

采用用户指定的 v03 作为主方法，不因后续某个测试日表现更好而更换参数。
不以期刊分区推定录用标准，也不预设本方法一定优于所有对照。
暂不增加 MADDPG、集中式 SAC/PPO、GRU 和 mixer 消融。
不将未经消融验证的网络组件单独宣称为创新点。

## 2. 固定主方法

主方法配置：`src/config/algs/facmac_ea_tune_v03_long.yaml`。
环境配置：`src/config/envs/microgrid.yaml`。
共享配置来源：`src/config/default.yaml`。

| 项目 | 计划值 |
| --- | --- |
| 环境版本 | `facmac_dispatch_v3`，3 个智能体 |
| 训练预算 | 每次约 6,000,000 环境步，记录实际步数及末回合超出量 |
| 种子标签 | 0、1、2 |
| Actor 学习率 | `3e-4` |
| Batch / replay buffer / warmup | 128 / 50000 / 512 |
| Actor 隐藏维度 / mixer 维度 | 48 / 32 |
| 常规学习更新 | 每 2 个普通 episode 触发 1 次更新 |
| EA 更新 / 代数 | 每周期 3 次 learner 更新、1 代进化 |
| 设备与入口 | CPU，`uv run python src/direct_main.py` |

正式运行前通过入口加载并导出完整合并配置，核实上述数值及未列出的参数。
消融不直接套用通用实验默认值，应与 v03 的实际配置一致。
冻结环境、奖励、设备约束、原始 CSV、训练/验证/测试划分和预测信息。

## 3. 算法对比

| 编号 | 方法 | 作用 | 训练次数 |
| --- | --- | --- | --- |
| B1 | 合理规则调度 | 可部署的工程基准 | 0 |
| B2 | 完美预测 MILP | 理想信息下的经济性参考 | 0 |
| L1 | 纯 FACMAC | 主方法的直接基线，同时承担去 EA 消融 | 3 |
| L2 | MAPPO | 独立的合作多智能体强化学习对照 | 3 |
| L3 | FACMAC + EA，v03 | 主方法 | 3 |

无控制结果可作为补充列，不用它替代合理规则调度。
规则调度应按当前可用信息设计，例如固定分时电价规则、SOC 安全边界、
满足负荷后的发电/储能/互济优先级；只用训练或验证数据确定阈值，
在查看测试表现前冻结规则，禁止使用未来实际负荷或光伏。

MAPPO 属于待实现的独立对照，不通过修改 FACMAC YAML 冒充另一算法。
其接入属于后续实施范围，需要明确批准并先确定独立模块及入口集成方案，
不在当前仅允许 FACMAC 的实现约束下直接修改算法结构。
已有 SB3 PPO 不是自动等价的 MAPPO，也不能直接复用旧环境下的分数。

## 4. 最小消融

| 编号 | 变体 | 相对 v03 的唯一方法变化 | 训练次数 |
| --- | --- | --- | --- |
| A1 | 去掉 EA，即 L1 | 关闭种群 rollout、进化及对应同步 | 已计入 L1 |
| A2 | 去掉变异 | `mutation_prob: 0.0`，保留其他 EA 机制 | 3 |
| A3 | 去掉交叉 | `crossover_prob: 0.0`，保留其他 EA 机制 | 3 |

合计 5 个学习配置 × 3 个种子 = 15 次正式训练，而非额外做 15 次消融。
去 EA 会自然移除 EA 专属的采样及更新，需披露实际 rollout 和梯度更新数量，
不能将其描述为计算量完全相同的单开关实验。

现有 `facmac_no_ea`、`facmac_ea_no_mutation`、`facmac_ea_no_crossover`
可参考机制，但需新增与 v03 对齐的独立配置文件，不能直接假设原配置已对齐。
保留已有配置及产物，不覆盖已跑版本。

可选扩展：同时关闭变异和交叉，保留筛选及精英复制。
仅在结果难以区分“进化算子收益”与“种群筛选收益”时追加，不列入最低工作量。
RL→EA 注入消融暂不做。

## 5. 公平训练与模型选择

1. 所有学习组使用相同训练数据、环境步上限和评估频率。
2. 环境步包括 EA 种群评估消耗；正式跑前核实计数器覆盖范围，不能只计 RL rollout。
3. 同时记录训练墙钟时间、吞吐量、梯度更新次数和策略评估次数。
4. FACMAC 系列保持网络与非消融参数一致；MAPPO 使用适配自身算法的合理参数，
   在验证集给出有限且公开的调参预算，不强行照搬 FACMAC 学习率或更新规则。
5. 执行时 Actor 只能使用统一约定的局部观测；集中 critic 使用的信息范围明确记录。
6. 各组统一是否使用循环网络及历史信息。确有差异时明确披露，不混淆为纯算法收益。
7. 只用固定验证集选 checkpoint；不能用测试成本挑训练种子、Actor 或超参数。
8. 主方法主表预先指定使用验证选出的 RL Actor；EA Actor 作为单独补充结果。
   不对每个测试日分别挑 RL/EA 中较好的那个。
9. 当前入口没有完整固定 Python/fastrand/Gym 等所有随机源。
   现有种子标签不能表述为完全配对复现。正式阶段应先审计并统一随机源协议；
   若因此改变训练实现或复用条件，记录版本差异，不能混算为同一协议。

## 6. 独立测试与库存边界

当前用于调参的验证日，包括 8 日 checkpoint 验证和候选日
`[740, 766, 808, 862, 880, 904]`，不能重新标记为独立测试集。
正式实施前审计已有时间划分，从未用于调参的保留时段确定测试集合。
在看各算法测试结果前保存划分文件及哈希；具体测试日期待审计后填写，不臆造。
测试需覆盖不同负荷与光伏水平，若数据跨度允许则覆盖季节差异。

主经济性评价建议使用固定的连续测试时段，时段内 SOC 跨天传递。
所有方法从同一初始库存开始；报告末端库存差异及库存修正诊断。
不能直接把每日独立重置 SOC 的展示成本当作长期持续运行成本。

MILP 与学习方法保持设备约束、成本口径和起始库存一致。
主对照采用不额外强制每日循环 SOC 的共同边界；若另跑循环 SOC 的 MILP，
单独标为“不同末端约束的参考”，不直接用于严格最优差距结论。
披露 MILP 的完美预测信息优势、求解状态、时间限制及最优间隙；
只有获得相应求解证据时才称其为最优解。
库存修正仅为诊断，不冒充准确的库存终端价值，也不修改训练奖励。

## 7. 指标与统计

| 类别 | 必报指标 |
| --- | --- |
| 经济性 | 测试总成本、日均成本、相对规则调度节约率 |
| 成本分项 | 购电、发电、储能循环、互济费用；按实现核实其他成本项 |
| 库存 | 期初/期末 SOC、库存修正成本及节约率，原始成本同时保留 |
| 稳定性 | 每种子完整测试集结果、3 种子均值与标准差、最差日成本 |
| 物理可行性 | SOC、充放电功率、机组功率、互济功率越限及能量平衡残差 |
| 设备使用 | 充放电量与双向活动、机组出力、购电量、互济量、弃光量 |
| 计算效率 | 训练时间、总环境步、吞吐量、在线推理时间；MILP 求解时间 |

节约率采用总成本之比：`1 - 方法总成本 / 规则总成本`。
若补充无控制节约率，另列且明确分母，避免混用。
先对每个训练种子汇总整个测试集，再跨种子统计；
不能把连续测试日当作相互独立的训练重复以夸大样本量。
3 种子仅作有限稳定性证据；差异小于种子波动时报告“未见可靠优势”，
不强行宣称统计显著或挑选最好的种子作为主结果。
电池活动用于解释调度，不以吞吐量越大越好作为优化目标。
